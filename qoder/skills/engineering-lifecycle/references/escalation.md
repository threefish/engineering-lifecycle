# 停止、升级与交付红线

> 加载时机：遇到歧义、冲突、越界或连续失败需要判断「是否该停下来问」时读取；正式交付前与 `validation-delivery.md` 一并读取。

## 1. 必须暂停并请示的情况

出现以下任一情况，暂停并向用户报告，不自行决定：

- 需求存在两种以上合理解释，且结果不可逆或影响面大。
- 改动触碰共享契约、公共 API、数据模型、权限与安全边界。
- 发现更值得解决的问题，需要改题。
- 证据冲突（代码 vs 文档 vs 运行态）且无法自行判定。
- 操作超出授权边界，或涉及生产数据、发布、不可逆动作。
- 需要修改其他仓库的内容（见常驻 `AGENTS.md` 的项目边界）。
- 连续两次尝试失败，且下一步只能靠猜。

低风险歧义可遵循项目已有约定，并明确说明采用的假设；不得为了推进任务而默默选择存在重大风险的方案。

## 2. 报告格式

**现状 + 证据 + 可选路径（含推荐）+ 需要的决定。**

不要只说「卡住了」，要给出让用户能一次拍板的全部信息。

## 3. 先出方案再执行的情况

- 修改核心业务规则。
- 调整数据库结构或数据模型。
- 修改权限或安全机制。
- 新增或修改对外 API，且可能产生兼容性影响。
- 重构公共基础模块或核心架构。
- 引入新的技术栈或第三方依赖。
- 其他明显具有较高回滚成本的变更。

方案至少说明：**目标、影响范围、实现思路、主要风险、验证方式、回滚方式**。

普通 Bug 修复、局部业务修改、测试补充和常规重构无需等待确认；范围锁定后按阶段自主执行。

## 4. 执行期行为约束

- 先理解与任务直接相关的代码、配置、接口和测试，再修改。
- 禁止无目的全量读取大文件和大日志；先用精确键名、错误码或关键字定位，再只读命中位置附近的内容。
- 不得根据文件名、方法名或用户描述自行猜测未确认的业务逻辑。
- 一次只做当前范围的事；额外问题记录并报告，不顺手修改。

## 5. 反模式清单

| 反模式 | 为什么错 | 替代做法 |
|---|---|---|
| 沉默执行表面需求 | 已知根因未解决却假装完成 | 指出并等待确认 |
| 凭文件名或方法名猜测行为 | 产出与真实契约不符 | 先读实现与调用链 |
| 顺手修复无关问题 | 扩大范围、放大回归面 | 记录并报告，另开事项 |
| 每步都问用户 | 打断协作节奏 | 对齐一次，范围锁定后自主 |
| 连续硬试同一错误 | 浪费上下文与时间 | 两次无进展即上报 |
| 报告只讲做了什么 | 无法判断是否可信 | 结论 + 证据 + 验证状态 + 风险 |
