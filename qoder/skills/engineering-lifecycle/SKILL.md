# 工程工作流（决策 → 实现 → 交付）

本技能是详细工程规范的按需入口。常驻规则（安全红线、项目边界）不在本文件内，以 `AGENTS.md` 为准。

核心原则：**谨慎优先于速度，简单优先于复杂，最小改动优先于重构，透明优先于猜测。**

冲突优先级：**安全与不可逆风险 > 事实 > 对齐 > 速度**。

## 1. 先定档

| 档位 | 典型触发 | 必须经过 | 可跳过 |
|---|---|---|---|
| 轻量 | 单点小改、文案修正、局部配置 | 事实核实 → 验证说明 | 需求对齐、多方案、反方审议 |
| 标准 | 新功能、行为变更、跨文件修改 | 对齐 → 问题定义审查 → 影响推演 → 验证 → 交付 | 三版方案（无明显分歧时）、历史考古 |
| 重型 | 架构调整、公共契约或数据模型变更、跨模块重构 | 全部环节 + 反方审议 + 回滚预案 + 当次明确确认 | — |

拿不准就升档：升档花的是时间，降档可能花的是返工与事故。

## 2. 产出红线

1. **不新增架构机制**，优先复用既有的统一返回、异常、分页、审计、锁、配置、日志等基础能力。
2. 业务逻辑不进门面，门面不加事务。
3. **不臆造**：字段、接口契约、模块能力先核实，再动手。
4. 请求 / 响应模型放模型层，不放门面；新增错误码进对应业务域，不散落定义。
5. 日志、注释、错误文案使用中文（标识符保持英文）；日志必须参数化，禁止字符串拼接。
6. 对外数据格式遵循 [references/interface-contract.md](references/interface-contract.md) 第 5 节。
7. 不删除、不重命名既有公共类与方法签名，不修改历史契约拼写；需要变更时先说明影响面与迁移方式。
8. 保持分层依赖方向；跨层调用属于架构违规。
9. 删除或重构代码前先证明三件事：无调用方、无外部契约、有回归手段；缺一不做。
10. 不写死配置、密钥与环境地址；配置项进配置体系并说明默认值。
11. 交付前执行可用的编译 / 静态检查 / 测试自检，并**如实区分「已编译验证」「已运行验证」与「未验证」**，不虚构结果。

## 4. 流程总览

```
定档 → 三问（真问题？手段还是目标？边界在哪？）
     → 对齐（只问影响决策的问题，锁定目标与 Non-goals）
     → 设计（六维影响 + 简单性检验 + 反方审议）
     → 实现（分层落位 + 主题细则按需加载）
     → 卡住（停止条件命中即上报，不靠猜继续）
     → 验证（已编译 / 已运行 / 未验证，如实标注）
     → 交付（结论 → 证据 → 风险 → 回滚）
     → 复盘（共性根因 → 规则 / 自动化 / Skill）
```

## 5. 最低要求

- 先理解现有代码与调用链，再做最小必要修改。
- 大文件和大日志先用精确键名或关键字定位，再局部读取；禁止无目的全文加载。
- 影响正确性、安全性、数据一致性或兼容性的歧义必须先询问。
- 普通修复直接执行；高风险变更先给出目标、范围、实现、风险、验证和回滚方案。
- 未完成实际验证时，不得声称测试、构建或发布成功。
