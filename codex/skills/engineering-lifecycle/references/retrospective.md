# 考古、认知、效率与复盘

> 加载时机：删除 / 重构 / 交接前，或需要归因迭代瓶颈、事故复盘时读取。按需使用，不要求每个任务都做。

## 1. 历史考古（在删除、简化、重构之前）

- 手法：提交历史与 blame → 关键 PR / issue / 设计文档 → 还原当时的约束（版本、兼容、性能、合规）。
- 三分类：
  - **有意设计**：保留，并补充注释或文档，避免下次被误删。
  - **历史包袱**：记录移除条件，进入待办。
  - **为已消失问题引入**：可移除，但必须先做回归验证。
- **移除三证**（缺一不删，对应 `SKILL.md` 产出红线第 9 条）：
  1. 无调用方：静态检索证明，含反射、配置、脚本等隐式引用。
  2. 无外部契约：接口、数据结构、配置项、事件均无外部依赖。
  3. 有回归手段：测试或可复现的手工验证路径。

## 2. 认知成本审计（在交接、评审、重构之前）

- **新工程师测试**：假设一位能力强但零上下文的工程师接手，只看代码与文档，能否在合理时间内完成一次典型修改？卡在哪一步？
- 红旗清单：
  - 命名与职责不符，或同一概念多个名字；
  - 抽象层级过多，读一条链路要跳五个文件；
  - 隐藏的时序依赖、隐式约定、口口相传的规则；
  - 必须读实现才能理解的接口。
- 输出：Top 3 认知热点 + 简化方案 + 暂不简化的理由（当风险大于收益时）。

## 3. 效率剖析（在迭代慢、评审慢、返工多时）

- 取样：最近 N 天的 PR / 任务，量化首次响应时长、评审轮次、提交到合并时长、返工次数。
- 看**分布尾部**而不是均值：最慢的那几个才是瓶颈所在。
- 归因四类：
  - 等待信息（需求不清、上下文缺失）
  - 流程阻塞（评审人、CI、环境）
  - 质量返工（测试缺失、方案反复）
  - 范围蔓延（PR 过大、夹带无关改动）
- 输出可执行改进：拆分 PR、补充模板、前置自动检查、明确评审时限。每条改进要能在一个迭代内验证效果。

## 4. 复盘与沉淀：让同样的成本只付一次

**复盘对象**：Bug、返工、回滚、重复修改——不只看单次事件，要找跨事件的**共同根因**。

**方法**：不问「谁错了」，问「哪个环节允许它发生」。时间线 → 直接原因 → 共性根因 → 拦截点（本可以在哪一步被拦住）。区分一次性失误（记录即可）与结构性缺陷（必须沉淀）。

**三类沉淀**：

| 沉淀形式 | 适合 | 示例 |
|---|---|---|
| 规则 | 需要人判断的约束 | 写入 `AGENTS.md` / `SKILL.md` 或评审清单的一条红线 |
| 自动化 | 可机械判定的检查 | 静态检查、测试、CI 门禁、脚本 |
| Skill / 模板 | 可重复的完整流程 | 复盘模板、排查手册、代码生成骨架 |

每条沉淀必须有：**触发条件、执行方式、验证方式**；无法验证的沉淀不写，避免文档垃圾。

**复盘的验收问题**：「同样的问题，下次会在哪一步被拦住？」答不出来，说明复盘没有完成。

## 5. 本节反模式

| 反模式 | 为什么错 | 替代做法 |
|---|---|---|
| 以「历史遗留」为由删除 | 可能删掉有意设计 | 考古三分类 + 移除三证 |
| 复盘落在「加强测试」 | 不可执行、不可验证 | 落到规则 / 自动化 / Skill，写明验证方式 |
| 看均值找瓶颈 | 尾部才是真实卡点 | 分析最慢的若干样本 |
