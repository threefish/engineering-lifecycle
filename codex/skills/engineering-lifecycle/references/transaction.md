# 业务与事务

> 加载时机：涉及写操作、事务边界、并发锁、异步任务、跨系统副作用的改动前读取。

## 1. 事务边界

- 事务边界只出现在业务层；门面永不开事务。
- 写操作失败必须回滚；只读操作显式声明只读意图。
- 事务范围尽量小：校验、远程调用、重计算放在事务外。

## 2. 事务内禁止事项

- 禁止远程调用（HTTP/RPC）、消息发送、文件 IO 与长耗时操作。
- 事务内只做：必要校验 + 数据读写 + 业务状态变更。

## 3. 事务后置副作用

- 通知、消息、事件发布、外部同步等提交后副作用走统一的事务后置机制。
- 前置判断：若副作用失败，业务是否允许提交；不允许则改为可补偿的中间状态（如待同步标记 + 补偿任务）。
- 补偿与重试必须幂等：同一请求重放不产生重复效果。

## 4. 幂等

- 所有可能被重试的入口（接口、消费者、任务）都要有幂等策略：唯一键、状态机前置校验或幂等表。
- 幂等窗口与业务时间约束一致，避免过期请求误放行。

## 5. 锁与并发

- 锁的范围最小化（单资源优先），必须设置超时，禁止无超时锁。
- 多锁获取顺序全局一致，防死锁。
- 优先乐观锁（版本号）处理低冲突更新；悲观锁只用于强一致写热点。
- 「查询-判断-写入」竞态必须用唯一约束或锁收口。

## 6. 异步

- 异步任务不依赖请求线程上下文（登录态、traceId、租户）；必要上下文显式传递。
- 异步失败必须有归宿：重试、告警或死信，不得静默吞掉。
- 线程池使用统一托管配置，禁止随手新建无界线程池。

## 7. 失败传播

- 业务失败不得吞异常：保留现场（日志、链路标识），按错误码向上传递。
- 部分成功的中间态必须可识别、可收敛，不留悬空数据。
