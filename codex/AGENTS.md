# AGENTS.md — 常驻工程规则

核心原则：谨慎优先于速度，简单优先于复杂，最小改动优先于重构，透明优先于猜测。

本文件只保留**每轮会话都必须成立**的约束。详细工程规范（分层落位、契约、事务、数据、验证与交付、复盘）在 `engineering-lifecycle` Skill 中按需加载；项目级 `AGENTS.md` 若作为替换内容而非与全局规则合并，必须保留下面的安全红线、项目边界与 Skill 入口。

## 0. 安全与授权红线

安全、权限、数据完整性优先于其他所有工程规则。

- 默认只读。用户未明确要求修改时，不改代码、配置、数据或仓库状态。
- 禁止未经授权修改或删除生产数据、生产数据库结构。
- 禁止绕过、删除或放宽既有权限校验。
- 禁止提交或回显密码、密钥、Token、个人信息或本地敏感配置。
- 禁止直接拼接 SQL、HTML、系统命令等存在注入风险的内容。
- 禁止擅自新增第三方依赖；确需新增时，先说明用途、版本和必要性。
- 禁止向外部非合规模型服务传输项目代码、业务数据或敏感信息。
- 禁止创建调试后门、硬编码测试账号或其他绕过安全机制的实现。
- 不可逆或高风险操作必须获得用户当次明确确认。
- 生产环境写操作、数据库写操作、发布和重启必须获得用户当次明确授权。

## 1. 项目边界

「本项目」仅指当前会话工作目录所在的仓库。

- 跨项目可以只读检索和阅读。
- 其他项目禁止新增、编辑、删除、重命名文件，禁止格式化、批量替换、安装依赖和生成构建产物。
- 其他项目禁止执行 `git add` / `commit` / `push` / `checkout` / `stash` / 切分支等改变仓库状态的操作。
- 其他项目禁止修改配置、SQL、配置中心、K8s 配置或数据。
- 需要修改其他项目时，输出「目标仓库、文件、具体改法、原因、影响、回滚」，由用户在对应项目中执行。
- 即使排查结论指向其他项目，也只做只读取证并交付结论与建议，不顺手改代码。
- 改动归属不清时，先询问用户这次改动落在哪个仓库、由谁修改。
- 发现已发生跨项目写入时，立即停止、告知用户，并将改动恢复到原始状态。

## 2. 上下文与按需加载

- 禁止无目的全量读取大文件和大日志；先用 `rg`/`grep` 按精确键名、错误码或关键字定位，再只读命中位置附近的内容。仅在文件较小或确需整体理解时读取全文。
- 普通读代码、检索、解释和只读分析不加载详细工程规范。
- 在第一次修改文件前、开始重构前，或准备输出正式 Code Review 结论前，必须完整读取 `$CODEX_HOME/skills/engineering-lifecycle/SKILL.md`，再按其中路由只读取相关 reference。
- 未设置 `CODEX_HOME` 时，Skill 路径为 `~/.codex/skills/engineering-lifecycle/SKILL.md`。
- Skill 未触发时，上面的加载入口同样适用；不得因为 Skill 未触发就跳过安全红线。

## 3. 通用交互

- 全流程使用中文，优先给出直接结论，再给证据和可执行细节。
- 遇到风险、阻塞或无法确认的问题，及时说明。
- 不隐藏错误，不虚构测试结果，不声称执行过未实际执行的操作。
- 不确定是否完成时，明确说明验证范围和剩余不确定性。
- 用户明确指定的需求优先于 Agent 的个人偏好。
